# Maintenance and Backup — PLANNED

> **PLANNED. Nothing is deployed; nothing is being maintained.**

## Patching

**[VERIFIED FACT]** SSM Patch Manager carries no additional charge on EC2 instances ([AWS Systems Manager pricing](https://aws.amazon.com/systems-manager/pricing/)).

**[DESIGN DECISION]** Patch at session start, not on a schedule. Instances are stopped between sessions, so a scheduled maintenance window would require the lab to be running — which is the opposite of the cost strategy.

```
Session start ──▶ SSM Patch Manager scan ──▶ apply ──▶ verify services healthy
```

An unpatched internet-connected host is exactly the profile of a lab that becomes an incident. Patching is not optional because the lab is "just a lab".

## Component updates

| Component | Approach |
|---|---|
| OS packages | Patch Manager at session start |
| Wazuh | Review release notes; update deliberately, not automatically |
| Shuffle | Pull updated images deliberately |
| Detection content | Version-controlled; changes through pull request |

**[DESIGN DECISION]** No automatic major-version upgrades. A silent upgrade that changes rule syntax or index structure turns a working lab into a debugging session. Update when you have time to fix what it breaks.

**[DESIGN DECISION]** Before any component upgrade: export detection rules and workflow definitions to git. That export is the rollback.

## Backup strategy

**[DESIGN DECISION]** Configuration is the asset. Event data is not.

| Asset | Backed up | How | Why |
|---|---|---|---|
| Detection rules and decoders | **Yes** | Git | Original work; expensive to recreate |
| Shuffle workflows | **Yes** | Git, credentials stripped | Original work |
| Wazuh configuration | **Yes** | Git, credentials stripped | Reproducible setup |
| Documentation and test results | **Yes** | Git | The record of what was actually observed |
| Alert and event data | **No** | — | Lab activity; reproducible from test cases |
| Instance state / AMIs | **No** | — | Rebuildable from documented procedure |

**Git is the backup.** Not an EBS snapshot schedule.

**[DESIGN DECISION]** No routine EBS snapshots. Snapshot storage is charged for the space consumed ([Amazon EBS pricing](https://aws.amazon.com/ebs/pricing/)), and routine snapshotting of a lab means paying indefinitely to keep data that can be regenerated by re-running a test case.

**Exception:** a single snapshot before a deliberately risky change — a major Wazuh upgrade, an experimental index change. **That snapshot is deleted once the change is verified.** A snapshot taken "just in case" and never deleted is a permanent charge for a moment nobody remembers.

### Recovery

| Loss | Recovery |
|---|---|
| Detection rule broken | `git revert`, restart manager |
| Workflow broken | Re-import from git export |
| Wazuh host lost | Rebuild from deployment plan; re-apply rules from git |
| Shuffle host lost | Rebuild; re-import workflows from git |
| Whole lab lost | Rebuild from documentation — **this is the real test of whether the documentation is good enough** |

That last row is the point of writing the deployment plan properly. If the lab cannot be rebuilt from the documentation, the documentation is wrong.

## Cost hygiene

Weekly:

```
□ Cost dashboard vs budget
□ Instances stopped
□ No unattached EBS volume
□ No unattached Elastic IP
□ No forgotten snapshot
□ No resource outside the Project tag
□ No resource in another region
```

**[DESIGN DECISION]** The unused-resource sweep is a named weekly task, not something done when the bill looks odd. By then it has already been paid.

## Log and index hygiene

| Check | Cadence |
|---|---|
| Index size vs volume capacity | Weekly |
| S3 lifecycle rules still applied | Monthly |
| Flow log volume still proportionate | Weekly in month 1, then monthly |
| Retention still matching the documented intent | Monthly |

Flow log volume is the logging cost that scales with activity. It is reviewed early and often enough to catch drift.

## Security maintenance

| Task | Cadence |
|---|---|
| Access review — identities, permissions, MFA | Monthly |
| Confirm zero access keys exist | Monthly |
| Security group review — inbound rules must remain zero | Monthly |
| Detection tuning log review | Monthly |
| Teardown plan re-read for accuracy | Monthly |
| Dependency and CVE review for Wazuh and Shuffle | Monthly |

## Documentation maintenance

**[DESIGN DECISION]** Documentation is updated in the same change as the thing it describes — never "later".

A README describing last month's behaviour is worse than no README, because it is believed. When deployment reveals that a documented step is wrong, **fix the document in the same session**, including when it makes the original plan look wrong. That correction is the most valuable thing in the repository.
